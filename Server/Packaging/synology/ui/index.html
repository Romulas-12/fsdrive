FSDrive

Ще один крок: налаштуйте службу FSDrive

DSM запускає сторонні пакети без прав адміністратора, а FSDrive має записувати файли від імені кожного користувача. Це налаштовується один раз, одним із двох способів. Сторінка помітить це сама.

Спосіб 1, Планувальник завдань (рекомендовано: зберігається після оновлень DSM)

  1. Control Panel → Task Scheduler → Create → Triggered Task → User-defined script.
  2. General: Task FSDrive, User root, Event Boot-up.
  3. Task Settings → Run command: команда нижче. Натисніть OK, виберіть завдання й натисніть Run.

Спосіб 2, через SSH

Загальні

FSDrive синхронізує файли між NAS і комп'ютерами користувачів. Файли зберігаються на NAS звичайними теками в домашніх або спільних теках, тож лишаються доступними через SMB, у File Station та інших службах DSM. Користувачі входять обліковими записами DSM; файли завантажуються на пристрій, коли їх відкривають.

Де зберігати файли

Примітка: FSDrive прив'язує теку до UID облікового запису DSM. Теки за іменами (/volume1/<тека>/<ім'я>) легше знайти на NAS, але якщо обліковий запис видалити й створити знову з тим самим іменем, новий UID не отримає доступу до наявної теки, доки адміністратор не підтвердить прив'язку («Прив'язати теку» в розділі «Користувачі»). Теки за UID (/volume1/<тека>/<UID>) прив'язуються однозначно й підтвердження не потребують. Нову спільну теку можна створити в Control Panel → Shared Folder.

Віддалений доступ

У локальній мережі пристрої з'єднуються з NAS напряму: сервер сам повідомляє їм свою адресу. Поза локальною мережею пристрої використовують вибраний нижче спосіб. Перемикання між ними автоматичне.

Зовнішнє з'єднання

Пристрій створює SSH-тунель до вашого шлюзу (наприклад, VPS) за власним ключем. Ключ пристрій отримує в локальній мережі. Пароль DSM через інтернет не передається, порти NAS назовні не відкриваються.

Зворотний проксі (наприклад, Nginx Proxy Manager або вбудований у DSM: Control Panel → Login Portal → Advanced → Reverse Proxy) із сертифікатом HTTPS переадресовує запити на порт FSDrive на NAS. Вхід — ім'ям і паролем DSM. У налаштуваннях проксі для цього хоста вимкніть HTTP/2 і буферизацію запитів.

Роутер переадресовує зовнішній порт на порт FSDrive на NAS (8740). З'єднання шифрується ключем сервера, який пристрій запам'ятовує під час першого входу. Тому вперше входьте в локальній мережі або звірте код ключа сервера в розділі «Загальні». Вхід — ім'ям і паролем DSM.

Стан

Файл fsdrive-gateway-setup.sh збережено. Перенесіть його на шлюз (Debian/Ubuntu з OpenSSH) і виконайте від root, наприклад:

scp fsdrive-gateway-setup.sh root@gateway:
ssh root@gateway 'bash fsdrive-gateway-setup.sh && rm fsdrive-gateway-setup.sh'

Скрипт додає лише користувача тунелю й окремий блок sshd для нього, перевіряє конфігурацію і реєструє шлюз у FSDrive. Ключі пристроїв шлюз щоразу питає в FSDrive. У файлі є секрет шлюзу: після запуску видаліть його.

FSDrive блокує IP-адресу після 5 невдалих спроб входу, а обліковий запис — після 10 невдалих спроб протягом 15 хвилин. Блокування діє 15 хвилин. Автоблокування DSM (Control Panel → Security → Protection) працює окремо й стосується входу в DSM.
